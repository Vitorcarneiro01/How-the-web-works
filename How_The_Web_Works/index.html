Brief history of the web

The web began when a British scientist, Tim Berners-Lee, while working at CERN identified difficulty in sharing information between different groups. That was when, in March 1989, he developed a Web proposal [1] to help solve these problems. The project consisted in the use of hypertext, which is a way to link and access various information as a web (using hypertext documents) requested by the user. [2] And after, he invented the WWW (World Wide Web).[3] The internet is a global network connecting computers, while the WWW is a system of interconnected pages, which operates through the internet. In 1990, with Belgian systems engineer Robert Cailliau, [4] they developed a more detailed proposal for the WWW, based on connecting and sharing information through hypertext. Furthermore, He developed key components, namely HTML (a language that is used to structure the content from the web pages), HTTP (a protocol that allows communication and the transfer of information between the users’ browsers and servers) and URL (address used to find resources on the web).

Moreover, Tim created the first web address from a website in the world: info.cern.ch [5] and also, the first server, which was initially used by only a few users. Therefore, a ‘line-mode’ browser was developed to make the Web more accessible to users with access to CERN computers.[3] In August 1991, after he (Tim) announced his software on internet newsgroups, it started to spread around the world. In February 1993, the NCSA [7] at University of Illinois developed the first Mosaic, a graphical browser that supported different protocols. In addition, in April 1993, CERN released the WWW software into a public domain[6]. By the end of 1994 the web had more than 10 000 servers and around 10 million users.[8]

In October 1994, Tim Berners-Lee established the W3C,[9] with the aim of developing Web Standards and accessibility between different browsers and devices.

How a web page is delivered

Understanding how the web works involves many processes that happen behind the scenes when a user accesses a website.

The Client and the Server

A client is a device or software, such as Chrome or Safari, that requests information from a server. Servers are computers that receive the request and provide the resources to the client. Therefore, the server responds the user’s request by sending the required resources back to the client and are then processed by the browser. [10]

URL and DNS

The URL is used to identifies the requested resource, and DNS helps resolve the domain name to an IP address. URL (Uniform Resource Locator) is the address of the webpage, which can contain different components some of which are optional, like WWW, Top-level domain, file path, but the Scheme (Define the protocol used, like HTTP or HTTPS) and domain name (Identifies the name registered on domain, like Griffithcollege.com) are essential in a complete HTTP/HTTPS URL.

DNS (Domain Name System) is used to translate the domain to an IP address, like a phone book, helping the browser locate the correct server and send an HTTP request to the right place. [11]

TCP/IP

TCP/IP works by breaking data into small pieces and transmit it over the internet and provides a better stability a fluidity.

Imagine the train that is traveling from Mallow to Cork and back. A similar process happens on the internet communication which involves requests and respond flowing between clients and servers. On the internet the TCP/IP is a suite of protocols that allows devices to communicate with each other. TCP (Transmission control protocol) helps organize and ensure that the small segments of data arrive correctly and in the right order, if some data is lost during the transmission, TCP can retransmit the lost data. IP (Internet Protocol) is responsible for encapsulating the TCP segments into IP packets and providing the right address and routing the data to the correct destination. [12]

Hypertext Transfer Protocol

HTTP allow browsers and servers to exchange requests and response. A request may contain method, headers, and body, while response may contain the status code, header and, when is applicable, body together with the resource requested

HTTP uses some Methods for example GET (requests a resource from the Server). When the server responds, it sends a code to identify the request like ‘200 OK’ (which means success), ‘404 Not Found’ (client error), ‘500 Internal Server Error’ (server error) … [10]

HTTPS (Hypertext Transfer Protocol Secure)

HTTPS is the secure version of HTTP because it uses TLS (Transport Layer Security) to encrypt communication, protect data during the transmission, helping block unwanted users, read or change the communication in progress and verifying the server’s ID. To conclude, the server sends resources such as HTML, CSS, JavaScript and images to the browser processes these resources and use to display the webpage to the user. [10]

How web pages work

For a web page to be displayed correctly, some technologies are necessary, such as HTML, CSS, JavaScript, each of them has a specific function in making the web page work properly.

After the browser send a request to the server and receives a response, the response contain HTML files which provides the structure of the page. The HTML also contains references to CSS and JavaScript files, the browser can request separately. CSS controls the appearance of the web page, while JavaScript adds functionality and allows users to interact with different page elements.

When the browser reads the HTML file, it creates a structure called the DOM (Document Object Model) which has a tree structure. [13]. This allows the browser identifies and organises the HTML element (h1, p, a…)

Once the HTML is structured and created, the browser processes the CSS file included and determine the appearance of the webpage. CSS applies styling rules to the HTML elements, controlling how they are displayed. Meanwhile, JavaScript is used to change the content and interact with the elements using the DOM. JavaScript code is interpreted or compiled by the browser and the executed.

Finally, the browser performs the rendering process, which transform these technologies into visual content. During this process, the browser calculates the position and size of the elements (layout), paints their visual appearance(painting) and combines different layers (compositing), Therefore, if JavaScript changes the DOM, the browser may need to update the layout and appearance of the page, which allows the final webpage to be displayed on the user’s screen.
